# UX-02 — Navigation connexion vers inscription

Date : 16 octobre 2026. Périmètre : navigation publique `/login` → `/register`, sans création de compte, appel métier, e-mail ni modification de base.

## Diagnostic

La recette du 27 septembre signalait plusieurs clics sans navigation pendant une première session, alors que `/register` fonctionnait en accès direct. Avec l'état actuel du projet, l'échec historique n'est plus déterministe : avant la correction, l'accès direct et quatre variantes de clic aboutissaient déjà. Les clics dépendaient cependant encore de la transition client Next.js App Router/RSC et le navigateur enregistrait quatre requêtes RSC préchargées annulées pendant ces enchaînements. Aucun formulaire, calque ou écouteur global ne bloquait le lien ; les deux documents répondaient en HTTP 200.

La couche qui différait entre le cas défaillant et le cas fiable était donc la transition client conservée avec son cache. Le déclencheur temporel exact de l'ancienne session ne peut pas être reconstruit après les changements PERF-01, mais cette dépendance a été supprimée du passage critique.

## Correction

Le clic principal sur « Créer un compte » conserve son `href`, empêche uniquement la transition client et utilise `window.location.assign("/register")`. Il effectue ainsi la même navigation document que l'accès direct connu comme fiable, y compris après retour ou cache chaud. Les clics déjà annulés, non principaux ou avec Cmd/Ctrl/Shift/Alt ne sont pas interceptés et gardent leur comportement navigateur.

La règle est isolée dans `src/lib/navigation/auth-page-navigation.ts` et couverte dans `tests/auth-page-navigation.test.ts`.

## Validation

- Chrome local : accès direct réussi ; clic après chargement 733 ms ; clic après retour 697 ms ; clic après attente avec cache chaud 288 ms ; clic après rechargement 312 ms.
- Les quatre clics arrivent sur `/register`, affichent « Créer un compte entreprise » et exposent `navigationType: "navigate"`. Aucun échec HTTP n'est relevé. La console signale une ressource secondaire 404 sans réponse HTTP capturée ni effet sur la page.
- Tests dédiés : clic principal intercepté et assigné une fois ; six variantes natives non interceptées.
- `npm run check` : types valides, lint sans erreur bloquante et **211/211 tests réussis**.
- `npm run build` : réussi, **96 pages** générées.
- `git diff --check` : réussi.

Preuves : `outputs/ux02/browser-navigation.json` et `outputs/ux02/register-final.png`. Protocole manuel : `docs/operations/ux02/README.md`.

Le test utilise un profil Chrome neuf sur le serveur local. Il ne qualifie pas encore Safari/Firefox physiques, mais le mécanisme retenu repose sur une navigation document standard et le comportement des clics modifiés est testé sans dépendre du routeur Next.js.
